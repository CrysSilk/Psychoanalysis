# 「潜意识之境」项目需求分析与分工

## 1. 项目简介

「潜意识之境」（Realm of Unconscious）是一个面向普通访客与心理学初学者的精神分析主题科普网站。项目以“从首页主题入口出发、沿兴趣进入专题”的方式组织内容，通过理论介绍、人物时间轴、人格结构交互和梦境意象展示，帮助用户认识精神分析中的主要概念及其发展脉络。

本项目属于课程学习成果展示，内容用于知识科普与学习交流，不提供心理诊断、治疗或医疗建议。理论观点应作为特定学术传统中的解释框架呈现，不应被描述成对所有人的确定结论。

## 2. 用户对象与项目目标

### 2.1 目标用户

- **普通访客**：对心理学或梦境主题感兴趣，希望快速了解网站主题并自由浏览专题。
- **心理学初学者**：需要结构清楚、概念易读的入门内容，并能了解理论人物、概念间的联系。
- **课程评审者**：关注内容来源与科普边界，也会检查页面结构、交互体验、视觉完成度和团队协作成果。

### 2.2 项目目标

1. 将精神分析相关内容拆分为可独立访问、又彼此关联的专题页面。
2. 以首页和全站导航建立清晰的信息入口，鼓励用户按兴趣继续探索。
3. 通过统一的深空视觉和适度交互，提升知识浏览的连贯性与辨识度。
4. 让理论内容有参考来源，并明确梦境解释及其他心理学内容的科普边界。

## 3. 网站结构与页面需求

网站由全站共享布局和六个页面组成。共享布局包括顶部导航、全站宇宙背景、页面路由出口和页脚；各专题页面复用独立内容组件。

| 页面 | 路由 | 当前内容与用户目标 |
| --- | --- | --- |
| 首页 | `/` | 展示网站主题和主视觉；通过专题卡片进入基础概念、理论脉络、人格结构和梦境探索；提供参考资料及科普说明入口。 |
| 基础概念 | `/guide` | 以卡片介绍潜意识、梦与联想、心理防御等入门内容，并引导用户继续了解理论脉络。 |
| 理论脉络 | `/theories` | 介绍理论发展背景，并以时间轴呈现代表人物、年代、学派、核心理论、简介、引言及资料出处。 |
| 人格结构 | `/personality` | 介绍弗洛伊德人格结构模型中的本我、自我和超我；用户可选择概念并查看当前选择反馈。 |
| 梦境探索 | `/dreams` | 展示梦境意象及其显性内容、理论视角下的解释示例和相关机制，并说明梦的改装机制。 |
| 参考资料 | `/references` | 集中展示项目参考书目和免责声明，说明网站内容范围及进一步求助建议。 |

### 3.1 首页浏览路径

首页首屏需要先表达“探索意识之外的心理经验”这一主题，再提供进入专题的主要行动入口。首屏之后的探索卡片负责呈现专题摘要和跳转方向；参考资料提示应让用户能够找到来源及内容声明。首页不承担所有理论内容的完整讲解，详细内容由对应专题页承载。

### 3.2 理论人物时间轴

- 从理论数据文件读取人物节点，展示人物姓名、所属学派和活动年代等概要信息。
- 点击节点展开详细卡片，再次点击可收起；多个节点允许同时展开，便于比较不同人物。
- 详细内容包括核心理论、人物简介、代表性引言及参考来源。
- 桌面端采用时间轴布局，窄屏切换为单列阅读，节点与卡片不得挤压或溢出。

### 3.3 人格结构交互

- 页面分别呈现本我（Id）、自我（Ego）、超我（Superego）的名称、说明和理论定位。
- 点击卡片后更新选中样式及“当前选择”反馈；选中状态通过 Pinia 统一管理。
- 交互卡片应提供清晰的点击状态、键盘焦点，并能在窄屏下换行展示。

### 3.4 梦境实验室

- 梦境条目与展示组件分离，页面按数据逐条展示意象、显性梦境、解释示例和关联机制。
- 机制说明区介绍凝缩、移置、象征化、润饰等概念。
- 梦境条目和机制条目应便于后续维护与扩充，不要求为增加内容重写展示逻辑。
- 必须在模块显著位置以及解释内容附近说明：这些内容是理论视角下的示例，不构成个人心理判断。

### 3.5 参考资料与声明

- 参考资料页面集中维护书名、作者及必要的出版或章节信息。
- 梦境内容、理论内容和书目之间应尽量保持来源对应，避免出现无法追溯的知识陈述。
- 免责声明说明项目的课程科普性质；对持续心理困扰者建议寻求具备相应资质的专业人士帮助。
- 页脚保持轻量，展示项目名称、简介和版权信息，不重复维护完整书目。

### 3.6 当前内容规模

- 首页包含四个主要专题探索入口。
- 理论时间轴的数据目前包括布洛伊尔、弗洛伊德、荣格、阿德勒、安娜·弗洛伊德和拉康，共六位代表人物。
- 梦境实验室目前展示十种梦境意象，并配有凝缩、移置、象征化、润饰四种梦的改装机制。
- 人格结构以本我、自我、超我三个概念为核心。
- 参考资料区当前维护七条书目或章节来源。

## 4. 视觉设计与动效需求

### 4.1 整体设计方向

- 采用深色背景、靛蓝/紫罗兰色调和柔和星云光晕，营造与“潜意识、深空探索”相呼应的视觉氛围。
- 标题、正文、说明文字和链接建立清晰的字号与对比层级；低优先级装饰不能压过内容。
- 导航、按钮、链接、卡片和专题页沿用统一的颜色、边框、间距及交互反馈。

### 4.2 首页星系与全站宇宙背景

- 全站背景使用 Canvas 绘制少量星点，包含缓慢漂移、微弱闪烁和有限距离内的连线；背景应保持低对比度，不影响文本阅读。
- 首页星系使用 Three.js/WebGL 点云表现星系盘面、旋臂、核球、星云及外围星尘，并缓慢旋转。
- 星系外缘通过稀疏粒子和透明度渐变融入页面背景，不应出现方形贴图边缘、明显圆形截止或硬裁切。
- 银心亮度应保留中心层次，不得过曝成大片纯白；主旋臂需与中心和外围星尘自然衔接。
- 星系组件与全站背景职责分离：前者服务首页主视觉，后者作为全站氛围背景。

### 4.3 动效、响应式与无障碍

- 桌面端与窄屏均应保持页面内容可读；导航窄屏可横向浏览，但不能导致整页横向滚动。
- 时间轴、梦境卡片和人格卡片需按视口宽度调整列数、间距或布局。
- 支持 `prefers-reduced-motion`：用户启用减少动态效果时，宇宙背景与星系停止持续动画，但仍可看到稳定的静态画面。
- 页面隐藏时暂停不必要的动画；组件卸载时清理动画帧、事件监听与 WebGL 资源。
- 装饰性 Canvas 与星云对辅助阅读不重复传达内容；交互控件需可识别、可聚焦并提供状态反馈。

## 5. 全局交互与数据组织

### 5.1 导航与全局状态

- 顶部导航对应六个页面，当前路由应有明显高亮；滚动页面时导航背景可增强以维持可读性。
- 导航栏提供背景音频开关；按钮状态应与播放状态一致，播放失败时将状态恢复为关闭。
- Pinia 管理跨组件共享状态，包括人格选择及音频开关等；滚动标记、时间轴展开集合等局部交互状态留在对应组件中。
- 路由切换应有一致的滚动行为和轻量页面过渡；共享导航、背景与页脚在路由切换中保持稳定。

### 5.2 内容数据

- 理论人物数据与时间轴展示组件分离，字段包含人物标识、姓名、学派、年代、核心理论、简介、引言和参考来源。
- 梦境意象数据与梦境实验室组件分离，字段包含条目标识、标题、显性内容、解释示例和关联机制；梦的改装机制另行维护。
- 参考资料集中维护，页面内容和参考信息应便于核对。
- 数据字段或共享 Store 接口发生变化时，应同步检查引用组件并及时通知相关成员。

## 7. 技术架构与开发协作

- **前端框架**：Vue 3 单页应用，由 Vue Router 提供六个专题路由。
- **构建工具**：Vite，负责本地开发和生产构建。
- **共享状态**：Pinia，保存跨页面或跨组件共享的交互状态。
- **视觉渲染**：CSS 负责布局和动效；Canvas 负责全站背景粒子；Three.js/WebGL 负责首页星系。
- **代码组织**：`views/` 负责页面级编排，`components/` 负责可复用内容区块，`data/` 保存理论与梦境数据，`stores/` 保存共享状态。
- **版本协作**：成员按功能分支提交，通过 Pull Request 审阅与合并；提交前检查自身变更，合并前验证主流程及受影响页面。
